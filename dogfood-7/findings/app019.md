## F1. Pytest skipped-only and xfailed-only runs establish false Green evidence

**Repro:** From the repository root:

```sh
bash dogfood-7/findings/repro-app019-skipped/reproduce.sh
```

The fixture first records a genuine assertion Red (`assert False`). Without any
test-file change, `REPRO_VERDICT=skip` makes the test call `pytest.skip`, and
`REPRO_VERDICT=xfail` makes it call `pytest.xfail`. The test ID is an actual
selected function, not a filename-only or empty-selection case.

**Actual:** Both `tdd green TEST-SKIPPED-001` invocations exit 0, append Green
entries, and their full gates print `SDD GATE PASS`, `1/1 tests Red→Green`.
Pytest executed no passing assertion: summaries are `1 skipped` and `1 xfailed`.
An unconditional skipped test also accepted a characterization Red and Green
during the initial probe, but ordinary assertion Red is sufficient to reproduce.

**Expected:** Reject Green when the selected tests all skip or xfail; do not write
Green evidence. A full project check executing only skipped/expected-failing tests
should report INCOMPLETE rather than PASS. The documented skipped-test guarantee
must also cover pytest's summary formats.

**Location:** `.github/skills/lean-sdd-tdd/scripts/sdd.mjs:2166–2173`, `cmdTdd`:
`allSkipped`, `noAssert`, and `NO_PASSED` omit pytest `1 skipped`/`1 xfailed`;
`:2613–2620`, `cmdGate`, accepts the zero exit code without checking that any
tests passed. `NO_PASSED` is defined at `:692`.

**Workaround:** Avoid skipped/xfail tests as evidence; externally inspect pytest
summaries or configure a pytest session-finish hook to return nonzero when zero
tests pass. A full gate alone is not a workaround for an entirely skipped suite.

**Severity:** high — false passing TDD evidence and full-gate verdict.

## F2. Python decorators above comment annotations are excluded from test hashes

**Repro:** From the repository root:

```sh
bash dogfood-7/findings/repro-app019-decorators/reproduce.sh
```

The second annotated test has this valid Python layout:

```python
@pytest.mark.parametrize("value", [0])
# @id TEST-DECORATORS-002 @verifies REQ-DECORATORS-002
def test_decorators_002(value):
    assert value == 1
```

After recording Red (`assert 0 == 1`), the script changes only `[0]` to `[1]`
in the test's parameter decorator. No implementation or assertion is changed.
A preceding annotated test ensures this decorator is not in the shared preamble.

**Actual:** Green exits 0 without requiring a new Red. The Red and Green
`fileSha` fields are identical:
`be991a30393c6900fcdd9571f07bd5d47fc122b493997b6ceba3cc4e19a1227c`.
The full gate exits 0 and reports `2/2 tests Red→Green`, although the passing
input is different from the failing input. The baseline's characterization
evidence is incidental; the affected second test has a genuine assertion Red.

**Expected:** Decorators belonging to an annotated Python function are part of
its test hash regardless of whether the comment annotation is before or after
them. Changing parameter data must invalidate evidence and make Green refuse
`test file changed since Red`.

**Location:** `.github/skills/lean-sdd-tdd/scripts/sdd.mjs:52–95`,
`testShaVariant` / `begin`: the backward decorator scan only runs when a Python
docstring annotation follows a `def`; a comment annotation begins its region
at the comment itself. The preceding test's top-level cut correctly excludes
the decorator, but it is never added to the following test's hash.

**Workaround:** Put the `# @id ... @verifies ...` comment **above all decorators**
or use the documented function-docstring annotation form; record a new Red
after any decorator edit. Do not rely on gate to detect this layout's drift.

**Severity:** high — parameter/skip/fixture decorators can change executable
test semantics while immutable Red→Green evidence remains falsely valid.
