## F1. Python `--missing-module` cannot accept the test's own new import

The test imports `calculate` directly from the intentionally absent
`missing_probe_module`; pytest is configured with `-q` to avoid its
`collected 0 items` header taking precedence over the load-error diagnosis.

**Actual:** exit 1, `RED REJECTED ... load/compile error, not an assertion failure`,

The rejection recommends `--missing-module` even though that flag was supplied.
The same failure occurred for the app's own absent `actor_runtime.scheduler`,
`actor_runtime.deadlock`, and `actor_runtime.remoting` imports.

**Expected:** the documented new-module exception should accept a missing
Python module named by the test's own import as a non-weak Red, while rejecting
unrelated dependency/import failures. Alternatively, explicitly document that
the option is not supported for Python and avoid recommending it there.

**Location:** `.github/skills/lean-sdd-tdd/scripts/sdd.mjs:669–686`,
`declaredMissingModule`: handles PHP and JS-style slash-prefixed import
diagnostics only; no Python `ModuleNotFoundError`/dotted import branch.
The load-error exemption calls it at lines 2191 and 2205.

**Workaround:** generate the missing module with `tdd stub TEST-PROBE-001`
and record an assertion/throwing-stub Red, as done for the application;
or use documented `--weak` and keep the resulting weaker evidence explicit.

**Severity:** med.

## F2. Pytest skipped/xfail-only runs produce false Green evidence and a PASS gate

**Repro** (fixture: `dogfood-7/findings/repro-app016-xfail/`):
```sh
S="node /home/nahisaho/GitHub/musubix6/.github/skills/lean-sdd-tdd/scripts/sdd.mjs"
cd /home/nahisaho/GitHub/musubix6/dogfood-7/findings/repro-app016-xfail
$S --root "$PWD" tdd red TEST-PROBE-001 && SDD_SKIP=1 $S --root "$PWD" tdd green TEST-PROBE-001 && SDD_SKIP=1 $S --root "$PWD" gate
```
Use `SDD_XFAIL=1` instead of `SDD_SKIP=1` for the second variant.
The fixture's collection hook applies the marker only when that environment
variable is set; **the test is unchanged** between Red and Green and still
contains `assert False, "real invariant still broken"`.

**Actual:** normal Red records the real assertion failure. Both marker
variants then record `GREEN ok TEST-PROBE-001` with exit 0.
Full gate reports `SDD GATE PASS`, `1/1 tests Red→Green`,
and `✓ cmd pytest`. Direct runner output confirms `1 skipped` or `1 xfailed`,
with **zero passing tests**. Unmarked execution still fails. Thus this is not
empty name selection or the already-reported filename-ID issue.

**Expected:** Green/refactor should reject all-skipped/all-xfailed pytest runs
without writing passing evidence. A check executing no passing tests should
not make the full gate PASS; it should be INCOMPLETE or fail.
This contradicts the skill's explicit all-skipped rejection guarantee.

**Location:** `.github/skills/lean-sdd-tdd/scripts/sdd.mjs:2168–2173`,
`allSkipped`, `noAssert`, `zero`, and Green's verdict at 2198–2200.
Those detectors cover other runners but omit pytest's skipped/xfail summaries.
`cmdGate` at line 2466 also trusts the successful pytest check exit.

**Workaround:** use `python3 -m pytest --runxfail` in both `testCmd` and checks
for expected-failure tests (verified to restore the real assertion failure),
and configure a runner wrapper to reject a suite/selection with zero passing
tests, including skip-only runs. Do not accept skipped/xfail-only evidence.

**Severity:** high.
