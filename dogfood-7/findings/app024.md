## F1. Multiline Python test signatures bypass Red-to-Green test hash locking

**Repro**

```sh
cd /home/nahisaho/GitHub/musubix6
python3 dogfood-7/findings/repro-app024-signature/reproduce.py
```

The self-contained fixture has two annotated tests. The second uses a multiline
function signature followed by an in-body docstring annotation:

```python
def test_probe_001(
    allowed=False,
):
    """@id TEST-PROBE-001 @verifies REQ-PROBE-001"""
    assert allowed is True
```

The reproducer records a normal assertion Red, then changes only the default
input to `allowed=True`, records Green without another Red, and runs the full
gate. It resets only its own fixture's ledger, so repeated invocation reproduces
the same result. Its first test has explicit characterization evidence; the
affected second test has an ordinary, non-weak assertion Red.

**Actual**

`RED ok TEST-PROBE-001 ... assert False is True`, followed by `GREEN ok
TEST-PROBE-001` and `SDD GATE PASS`. Red and Green both have `fileSha`
`0ffddc54fc06d5aaeb4ce06110404f5dafa38292bcaeee44f80a95b85a897d59`.
No implementation was changed: the test was made to pass by changing its input.
The full fixture gate reports 2/2 tests Red→Green, with only the separate baseline
test counted as characterization.

**Expected**

The complete test function signature, including default values, must belong to
that test's evidence hash. Green should refuse the edit as `test file changed
since Red`; a new Red should be required. In particular, multiline signatures
should have the same protection as single-line signatures.

**Location**

`.github/skills/lean-sdd-tdd/scripts/sdd.mjs:54–66`,
`testShaVariant`'s `begin()` helper. It recognizes a Python `def` only on the line
immediately preceding the docstring annotation, or two lines above a standalone
triple-quote opener. A multiline signature has `):` there instead, so `begin`
returns the annotation line. Because this is not the first annotated test, the
file preamble does not rescue the omitted signature. Both current `testSha` and
accepted compatibility hashes omit the edited default.

**Workaround**

Use comment annotations immediately above the full `def` signature, as the main
app does, or keep docstring-annotated signatures on one line. Do not treat Green
as proof of unchanged test input for multiline docstring-annotated tests.

**Severity:** med — changed test inputs can acquire false Green and full-gate
PASS, defeating the documented identical-test requirement.

text here is the function's own parameter default, with an unchanged assertion.

review confirmed the hash-function counterexample.
