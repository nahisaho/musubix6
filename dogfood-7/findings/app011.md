## F1. Open review findings with explanatory status suffixes bypass approval

Repro:
```sh
node dogfood-7/findings/repro-app011-1/reproduce.mjs
```
The fixture writes a hash-linked review with `verdict: pass`, `open: 0`, and
`| R1 | high | src/index.ts:1 | Open (awaiting fix) |`, then invokes `review check`
and `approve record probe --by ai:independent-reviewer --review review.md`.

Actual: `REVIEW OK` and `locked probe`; both commands exit 0 despite the unresolved finding.

Expected: Recognize the explicit Open table-cell status, detect the mismatched `open: 0`,
and refuse approval. Adding explanatory prose to a status must not silently mark it resolved.

Location: `.github/skills/lean-sdd-tdd/scripts/sdd.mjs:714`, `isOpenLine`.
Its table-cell regex requires the entire cell to equal an Open status; `reviewProblems`
(line 715) trusts the resulting undercount. `Open (awaiting fix)` does not match.
The documented schema permits explicit table-cell statuses and requires zero Open findings.

Workaround: Use an exact bare `Open`/`Pending` status cell and put explanations in a separate
column, or use `state: open`. Independently inspect review findings before locking.

Severity: med.

## F2. TODO-only node:test assertions can acquire Red/Green evidence and pass the full gate

Repro:
```sh
node dogfood-7/findings/repro-app011-2/reproduce.mjs
```
The fixture's sole annotated test is `{todo:true}` and asserts `false === true`.
It runs `init`, `tdd red TEST-PROBE-001 --characterization "TODO should never provide evidence"`,
`tdd green TEST-PROBE-001`, and full `gate`.

Actual: Every command exits 0. Red is recorded as characterization, Green is accepted,
and `SDD GATE PASS` reports `1/1 tests Red→Green`. Native node:test reports
`pass 0`, `fail 0`, `skipped 0`, `todo 1`; the assertion never succeeds.

Expected: Reject Red/Green and characterization when every selected test is TODO, just
as skipped/no-match tests are rejected; do not bless a failing TODO assertion as verification.

Location: `.github/skills/lean-sdd-tdd/scripts/sdd.mjs:692` (`NO_PASSED`) and
`:2162–2173` (`cmdTdd` zero-test detection). Node detection only catches positive skipped
counts, not TODO-only summaries. Gate then accepts this invalid ledger evidence.
The script's own rejection message says “the test is skipped/todo”; the enforced-rules
documentation promises skipped tests cannot provide Red/Green or characterization evidence.

Workaround: Remove TODO markers from verifying tests and require a selected test with
positive non-TODO passes. Do not record characterization for TODO cases.

Severity: high.

not re-reported. Final app validation used the full gate and all five workspace test checks.
