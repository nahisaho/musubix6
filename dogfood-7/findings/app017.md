## F1. Pytest suffixed names allow a sibling failure to become the target's Red

**Repro** (fixture: `dogfood-7/findings/repro-app017-1/`):
```sh
cd dogfood-7/findings/repro-app017-1
S="node ../../../.github/skills/lean-sdd-tdd/scripts/sdd.mjs --root $PWD"
$S init && python3 -m pytest -q test_selection.py::test_select_001_target && $S tdd red TEST-SELECT-001
```

**Actual:** The exact target passes, but SDD records `RED ok TEST-SELECT-001` with
`AssertionError: only the sibling failed`. The automatically generated
`-k test_select_001` also selects `test_select_0011_sibling`. The target has no failing assertion.

**Expected:** Select the requested test exactly, or reject attribution when only a
sibling fails. Supporting descriptive suffixes must not create false Red evidence.

**Location:** `sdd.mjs:2019–2024` (`testName`) returns the ID substring rather than
the complete function name; `sdd.mjs:2151–2160` (`cmdTdd` pytest collision guard)
excludes longer names only if `names.includes(me)`, which is false for
`test_select_001_target`.

**Workaround:** Name functions exactly like the lowercase underscore TEST ID
(without descriptive suffixes), or configure an exact pytest node-ID selector.
This is not the already-reported filename/empty-selection false Green: two real
tests execute, and the wrong test's failure is attributed to the target.

**Severity:** high (false Red undermines test-specific TDD evidence).

## F2. Changing Python import aliases preserves the test hash and permits false Green

**Repro** (fixture: `dogfood-7/findings/repro-app017-2/`):
```sh
python3 dogfood-7/findings/repro-app017-2/reproduce.py
```
The script resets this fixture's own ledger and test; records Red with
`from oracle import subject as value`; changes only that test import to
`from oracle import unrelated as value`; then runs Green and full gate.

**Actual:** `GREEN ok TEST-ALIAS-001` and `SDD GATE PASS`, with 1/1 Red→Green.
The test was edited to assert a different function. The implementation of
`oracle.subject()` remains unchanged and returns `False`, violating the REQ.
Both ledger entries have the same test hash.

**Expected:** Reject Green because changing the imported callable/alias changes
the test's assertion subject. Re-record Red for the changed test.

**Location:** `sdd.mjs:45–47` (`normImports`) reduces every Python
`from MODULE import ...` line to `from MODULE`, discarding both imported names and
aliases; `testShaVariant` uses this normalized preamble, so the mutation is invisible.

**Workaround:** Do not rebind imports between Red and Green. For a necessary
replacement, also change the test body and record a new Red. Alternatively use
`import oracle` and call `oracle.subject()` in the test body.

**Severity:** high (false Green and full gate PASS despite a test-subject change).
