## F1. Go external-package stubbing overwrites an existing real production `_stub.go` file

**Repro**

```sh
cd /home/nahisaho/GitHub/musubix6
sh dogfood-7/findings/repro-app030-overwrite/reproduce.sh
```

The fixture has external `package calc_test`, imports `example.org/stubproof/calc`,
and calls missing `calc.Add(2,3)`. The real production file `calc/calc_stub.go`
already declares `Existing() int { return 42 }`; it has no SDD stub marker.
The reproduction copies/restores this file so repeated runs preserve the fixture.

**Actual**

`tdd stub TEST-STUBPROOF-001` exits 0 and reports
`stubbed (throwing, compile-checked): calc/calc_stub.go`.
The existing file is replaced wholesale with `package calc` and a throwing
`Add`; `Existing` and its real source are deleted. Compilation succeeds because
the new test does not call Existing, hiding the loss of unrelated production code.
The reproduction prints `BUG: Existing production function was overwritten`.

**Expected**

Honor the documented “real code is never touched” guarantee: select a unique new
filename, or safely extend only a proven generated-stub file. The real Existing
declaration must survive unchanged.

**Location**

`.github/skills/lean-sdd-tdd/scripts/sdd.mjs`, `stubGo`, external `_test` package
branch: line 930 assigns `${last}_stub.go` whenever any production Go source
exists, without checking that filename; lines 977–978 write the rendered file
without checking whether it contains real code.
The in-package branch at lines 905–906 already chooses a collision-free path.
`references/stubs.md` promises that real code is never touched.

**Workaround**

Before external-package `tdd stub`, ensure `<package-directory>_stub.go` is not
real source; otherwise hand-write the missing skeleton instead. Restore the
original file if the generator has already overwritten it.

**Severity:** high — silent source-code loss from a documented non-destructive tool.
