## F1. Nested --root changed gate uses repository-relative Git paths and skips TDD evidence/projects

### Repro
Fixture: `dogfood-7/findings/repro-app006-1/` inside the existing musubix6 Git repository. No separate Git repository or commits are required.

```sh
cd dogfood-7/findings/repro-app006-1
node reproduce.mjs
```

The launcher compares `sdd.mjs --root . gate` with `sdd.mjs --root . gate --changed` on a passing test with **no Red/Green ledger**. It asserts the observed exits so the defect is repeatable.

### Actual
- Full gate: exit 1, `tdd evidence: 0/1 tests Red→Green`, `no Green recorded`.
- Changed gate: exit 0, `SDD GATE PASS`, `tdd evidence (changed scope): 0/0 tests Red→Green`.
- In the five-workspace application, changed gate also skips **all five** project checks with `no changed files in packages/...`, although every package is newly created/untracked.
- App output warns about unrelated `.github/skills/...` changes as “root-owned data/config changes”, despite the configured root being only this app. These were pre-existing changes and were not modified by this assignment.

### Expected
Changed files should be relative to `--root`, restricted to its descendants. Untracked app sources/tests should require their Red→Green evidence and run their owning project checks. Changes outside the app root should not appear in its gate.

### Location
`.github/skills/lean-sdd-tdd/scripts/sdd.mjs:2291–2295`, `changedFiles()`: runs `git status --porcelain -uall` with `cwd: ROOT` and directly stores its path fields. Git porcelain paths remain repository-root relative even when cwd is nested. Consumers compare these against app-relative paths at changed evidence selection and project ownership (`cmdGate`, around lines 2494 and 2553–2570).

### Workaround
Run the **full gate** without `--changed`, as done for this app. Do not interpret the changed-only `0/0` verdict as validation. A separate Git root would avoid the mismatch, but is unnecessary and was not created.

### Severity
**High** — a documented nested-root workflow falsely reports PASS while omitting required evidence and project checks.

## F2. Node no-match guard accepts a file-level pass when the filename contains the TEST ID

### Repro
Fixture: `dogfood-7/findings/repro-app006-2/`. The annotated test title correctly contains `TEST-NOMATCH-001`; the filename is `TEST-NOMATCH-001.test.mjs`.

```sh
cd dogfood-7/findings/repro-app006-2
node reproduce.mjs
```

The launcher records a genuine assertion-failing Red with the normal filter. It temporarily changes only `testCmd`'s name pattern to select no tests, attempts Green without changing implementation or test, then directly runs the still-failing test. The runner configuration is restored in `finally`.

### Actual
- Red: exit 0, recorded assertion failure (`0 !== 3`).
- Green with the empty-selection pattern: exit 0, `GREEN ok TEST-NOMATCH-001`.
- Direct `node --test TEST-NOMATCH-001.test.mjs`: exit 1, assertion still fails.
- Node 24 reports an unmatched file as one passing file-level test. Its output includes the TEST ID **only through the filename**, which is sufficient for the script's guard.

### Expected
Green must be rejected as no-match when no actual named test executes, regardless of the test file's name. A configuration/filter mistake must not manufacture Green evidence. The same issue affects characterization Red, which uses the same zero-match predicate.

### Location
`.github/skills/lean-sdd-tdd/scripts/sdd.mjs:2169–2170`, `cmdTdd()` / `nodeNoMatch`: requires only `plain.toLowerCase().includes(id.toLowerCase())`, not an executed test title. Node's file-level result satisfies this substring check.

### Workaround
Do not place TEST IDs in filenames; keep them in actual test titles. Verify that name filters execute the intended subtest, and run the full suite/full gate. The real app uses feature-based filenames, and its complete suite passes.

### Severity
**Medium** — false Green evidence after a no-match filter; an independently configured unfiltered full-suite check still catches the failing implementation.
