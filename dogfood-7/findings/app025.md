## F1. Go impact omits same-package production dependencies

### Repro

```sh
sh dogfood-7/findings/repro-app025-1/repro.sh
```

The fixture has `pkg/helper.go` declaring private `hash`, `pkg/api.go`
declaring public `Run` that calls `hash`, and `client/client.go` calling
`pkg.Run`. These are three separately annotated features. The real Go test
executes that chain and passes before the script query.

Application occurrence:

```sh
cd dogfood-7/app025-go-lsm-store
sh sdd.sh impact REQ-SST-002 --json
```

`sstable/sstable.go` calls `newBloom` and uses its methods from
`sstable/bloom.go`; store point reads depend on that table and bloom filter.

### Actual

The fixture query returns `impl:["pkg/helper.go"]`, `reachedFiles:[]`,
`otherReqs:[]`, and `reachedTests:[]`. The application query likewise reports
no reached files for the bloom requirement, omitting the table, engine,
compaction caller, and their tests. This is not the previously reported
methods-only receiver-resolution issue: the minimal fixture uses only free
functions.

### Expected

Follow the same-package `hash → Run` dependency, then its imported callers.
The fixture should reach `pkg/api.go`, `client/client.go`, its test, and the
API/client REQs. A conservative same-package fallback is preferable to an
empty false-negative dependency graph.

### Location

`.github/skills/lean-sdd-tdd/scripts/sdd.mjs`, `importRev()` Go branch,
approximately line 2823: same-directory symbol edges are added only when
the importer ends in `_test.go`, not for production `.go` files.
The cross-feature hint uses this same graph.

### Workaround

Manually account for same-package production callers; run full gate and
`go test -race ./...`. Keeping mutually dependent helpers in one annotated
implementation file avoids this particular graph gap.

### Severity

**med** — materially incomplete impact analysis/cross-feature warnings;
the full Go check still protects actual execution.

## F2. Go impact excludes imports of the module-root package

### Repro

```sh
sh dogfood-7/findings/repro-app025-2/repro.sh
```

The fixture is a valid multi-package Go module: root `root.go` implements
`Add`, and `consumer/consumer.go` imports the module itself using an explicit
alias and calls `root.Add`. A real consumer test passes.

### Actual

`impact REQ-ROOT-001 --json` returns `impl:["root.go"]` but
`reachedFiles:[]`, `otherReqs:[]`, and `reachedTests:[]`.
The imported root implementation is absent from the reverse graph.

### Expected

The query should reach `consumer/consumer.go`, its test, and
`REQ-CONSUMER-001`, just as it does for an imported subpackage.
This is distinct from the already-fixed nested `go.mod` mapping bug:
the fixture's `go.mod` is directly at `--root`, and the imported package
is that module's root.

### Location

`.github/skills/lean-sdd-tdd/scripts/sdd.mjs`, `importRev()` Go branch,
approximately line 2817: imported directories are filtered using
`d !== '.'` even when `goModDir(importPath)` correctly resolves to `.`.

### Workaround

Place shared implementations in a named subpackage, or account for root-package
importers manually and run the full gate. Do not rely on `impact`'s empty result.

### Severity

**med** — a normal Go module layout silently loses dependency and
cross-feature-warning coverage.
