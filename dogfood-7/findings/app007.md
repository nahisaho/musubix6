## F1. Nested --root loses changed paths and falsely passes without tests

**Repro** (from the musubix6 repository root; fixture must remain untracked):
```sh
S="node .github/skills/lean-sdd-tdd/scripts/sdd.mjs --root dogfood-7/findings/repro-app007-1"
$S gate --changed
$S gate
```
The fixture includes a T1 test-only characterization requirement, its recorded
Red/Green ledger, and a separate deliberately failing test. Its config selects
both tests for full checks, and uses `{changedTests}` for changed checks.

**Actual:** changed gate exits 0 (`PASS`, `0/0` evidence, `no changed files —
skipped`); full gate exits 1 on the failing assertion. The real untracked app
likewise reported `0/0` and skipped its entire configured test check.
`git status --porcelain -uall` run inside the nested root returns repository-root
paths (`dogfood-7/findings/repro-app007-1/tests/...`), not root-relative paths.

**Expected:** normalize/filter Git status paths to `--root` and run the changed
tests/evidence checks. An existing failing changed test must not receive PASS.

**Location:** `sdd.mjs:2291–2295` (`changedFiles`), consumed by
`cmdGate` at `2569–2572` and changed evidence scoping. `listFiles` uses
`git ls-files` which does return nested-root-relative names, unlike status.

**Workaround:** run full `gate` without `--changed`; do not rely on changed-only
evidence or skipped-check PASS in nested roots. No script modification made.

**Severity:** high — false-green validation of failing changed code.

## F2. JS stub scans sibling tests and invents methods on factory classes

**Repro:**
```sh
S="node .github/skills/lean-sdd-tdd/scripts/sdd.mjs --root dogfood-7/findings/repro-app007-2"
$S tdd stub TEST-FIXTURE-001
git diff --no-index /dev/null dogfood-7/findings/repro-app007-2/src/registry.js
```
Fixture baseline: selected test only asserts a literal. A sibling constructs
`const child = new Registry().create()` and calls `child.get()`. Registry creates
a distinct `Child`, whose genuine `get` method already exists.

**Actual:** stub modifies the existing real `Registry` class by appending
`get(..._args) { throw new Error('not implemented: Registry.get'); }`, even
though the selected test uses neither class nor method and all imports exist.
The same defect added `ShapeRegistry.get/set` to the real app while stubbing
unrelated OPT-010. Those erroneous additions were removed.

**Expected:** no source modification for this selected test. JS stubs should
use only shared preamble + selected test body; factory return values are not
provably instances of the factory's class.

**Location:** `sdd.mjs:1707–1709` computes `scoped`, but `prep` at
`1728–1730` uses full `src` as `S`; `jsExisting` passes that to `methodsOf`
at `1827`. `methodsOf:1447` captures `child = new Registry()` even when followed
by `.create()`, falsely attributing later child calls to Registry.
`references/stubs.md` promises requested-test scoping and proven receivers.

**Workaround:** inspect stub changes and remove wrong members; write missing
stubs manually for factory/chained-return tests. Fixture retains its clean
baseline so the command reproduces the unwanted addition.

**Severity:** medium — unrelated real code is silently modified with bogus API.
