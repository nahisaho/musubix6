## F1. Nested --root causes gate --changed to ignore all app changes and skip project tests

### Repro

From the musubix6 repository root, use the supplied minimal fixture under
`dogfood-7/findings/repro-app009-1/` (intentionally no TDD evidence):

```sh
node .github/skills/lean-sdd-tdd/scripts/sdd.mjs --root dogfood-7/findings/repro-app009-1 gate --changed
node .github/skills/lean-sdd-tdd/scripts/sdd.mjs --root dogfood-7/findings/repro-app009-1 gate
```

The fixture is a nested directory of an existing Git repository. No nested Git
initialization or commits are needed. Its `tests` project depends on `src`.

### Actual

Changed gate exits **0**, reports `SDD GATE PASS` and
`tdd evidence (changed scope): 0/0 tests Red→Green`, then skips the test check:
`no changed files in tests or its dependencies (src)`.
It also reports unrelated parent/sibling changes as root-owned configuration.

Full gate correctly exits **1**, reports `0/1 tests Red→Green` /
`TEST-CHANGE-001: no Green recorded`, and runs the actual test.
The app itself likewise reported changed-scope `0/0` despite all 45 tests being
untracked within its app root.

### Expected

Changes within `--root` must be normalized relative to that root, and changes
outside it excluded. The changed gate must check this test's missing evidence and
execute its project check; it must not give a false PASS.

### Location

`.github/skills/lean-sdd-tdd/scripts/sdd.mjs:2291–2295`, `changedFiles()`.
It invokes `git status --porcelain -uall` from `ROOT`, but porcelain paths are
relative to the enclosing Git repository root, not the invocation cwd. Those
paths are subsequently compared with app-relative annotated paths/project roots.
There is no Git-root-to-`ROOT` normalization or subtree filtering.

### Workaround

Use the documented final **full** `gate` (without `--changed`), which checks
all evidence and runs all project checks. Do not rely on `gate --changed` when
`--root` points to a subdirectory of an enclosing repository.
No skill/script files were modified.

### Severity

**high** — false success bypasses Red→Green evidence and project checks in
the nested-root application layout explicitly required by dogfood-7.
