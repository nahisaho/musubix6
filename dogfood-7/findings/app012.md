## F1. Node no-match detection mistakes an ID-bearing filename for an executed test

**Repro**

```sh
cd /home/nahisaho/GitHub/musubix6
sh dogfood-7/findings/repro-app012-1/repro.sh
```

The fixture uses the default Node test command shape. Its annotated ID is
`TEST-NOMATCH-001`, its filename is `TEST-NOMATCH-001.test.mjs`, and its actual
test title is `TEST-NOMATCH-0011 intentional nonmatching sibling`. The default
token-anchored name pattern correctly selects **no test bodies**.

**Actual**

On Node v24.21.0, the runner prints a passing file-level subtest:

```text
✔ TEST-NOMATCH-001.test.mjs
ℹ tests 1
ℹ pass 1
ℹ skipped 0
```

`tdd red TEST-NOMATCH-001 --characterization ...` accepts this no-match run as a
weak Red, `tdd green TEST-NOMATCH-001` accepts it as Green, and the full gate
reports `SDD GATE PASS`, `1/1 tests Red→Green`, exit 0.

Control: `node --test TEST-NOMATCH-001.test.mjs` executes the actual test and exits
1 with `AssertionError: this body must never provide a Green`. Therefore the
fixture's passing evidence is not the result of an executed passing assertion.
Renaming only the test file to `control.test.mjs` makes the identical
characterization command correctly return `RED REJECTED: no test matched the ID`
(exit 1). Restoring the ID-bearing filename reproduces the false acceptance.

**Expected**

Reject the characterization Red and Green as “no test matched the ID.” The
documented no-match rule applies even when Node represents the file itself as
one passing test; filename presence is not proof of an executed matching test.

**Location**

`.github/skills/lean-sdd-tdd/scripts/sdd.mjs:2172`, `cmdTdd()`:
`nodeNoMatch` checks `!plain.toLowerCase().includes(id.toLowerCase())` across the
entire output. The filename supplies the ID and defeats that check. The resulting
`zero` predicate does not block characterization or Green (`2173`, `2189–2190`).
Related promised behavior: `references/enforced-rules.md`, Node no-match
rejection (#119), token-anchored filters (#141), and skipped/zero-test rejection
for characterization (#140).

**Workaround**

Use descriptive test filenames that do not contain TEST IDs, ensure actual test
titles match the token-anchored ID, and run the unfiltered full test suite.
For a custom runner, require an actual matching test-body result, not merely an
ID anywhere in stdout or a file-level Node subtest.

**Severity:** high — false Green/evidence and a false full PASS can attest to a
test body that never ran, including one that demonstrably fails.
