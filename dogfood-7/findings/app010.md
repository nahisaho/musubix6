## F1. Nested `--root` changed gate falsely PASSes a failing implementation

**Repro**

From the repository root:

```sh
cd dogfood-7/findings/repro-app010-1
node run-repro.js
```

The fixture records a real assertion Red, implements Green, and confirms a full
gate PASS. It then changes `src/value.js` from returning 1 to returning 2 without
editing the test or evidence. It runs both gates and restores the original
implementation in `finally`. No git initialization, staging or commits are needed.

**Actual**

`gate --changed` exits **0** with:

```text
SDD GATE PASS
✓ tdd evidence (changed scope): 0/0 tests Red→Green
! cmd test: no changed files — skipped
```

The immediately following full `gate` exits **1** and reports the test's
`AssertionError`. The real application's nested changed gate similarly ignored
all untracked app files and checked 0/0 evidence despite a complete passing
full gate checking 25/25 tests.

**Expected**

Git status paths should be normalized from the actual Git repository root to
the configured SDD root, with sibling apps excluded. The failing changed
implementation must select its dependent test and make the gate fail. A
required check skipped due to an unresolved scope must never produce PASS.

**Location**

`.github/skills/lean-sdd-tdd/scripts/sdd.mjs:2291–2296`,
`changedFiles()`. `git status --porcelain -uall` reports repository-root-relative
paths even when its cwd is a nested app; the function returns them unchanged
while scan/trace/test paths are relative to `ROOT`.
The documentation in `references/enforced-rules.md` also promises skipped
checks are INCOMPLETE, contradicting this PASS.

**Workaround**

Use the documented **full `gate` without `--changed`** for nested SDD roots.
This was used throughout and for final verification. Do not trust the changed
gate's exit 0 in this layout.

**Severity:** high — silently accepts failing behavior and skips all changed
test/evidence checks in the prescribed dogfood layout.

## F2. JavaScript `tdd stub <ID>` generates methods used only by sibling tests

**Repro**

From the repository root:

```sh
cd dogfood-7/findings/repro-app010-2
node run-repro.js
```

The fixture contains two tests importing `Box`: TEST-STUB-001 calls only
`first()`, TEST-STUB-002 calls only `second()`. It invokes `tdd stub
TEST-STUB-001`, prints/asserts the generated source, then removes that generated
source in `finally` so the fixture remains reproducible.

**Actual**

The generated class includes both:

```js
first(..._args) { throw new Error('not implemented: Box.first'); }
second(..._args) { throw new Error('not implemented: Box.second'); }
```

The same defect appeared in the app: stubbing TEST-TOPICS-001 generated
`Log.publish` and `Log.read`, used only by sibling tests. Stubbing
TEST-LIFECYCLE-001 additionally generated methods/constants needed only by its
sibling tests.

**Expected**

The documented per-test scope is the shared preamble plus the requested test's
body. Shared imports may introduce the class, but a method used exclusively in
another annotated test must not be generated for the requested test.

**Location**

`.github/skills/lean-sdd-tdd/scripts/sdd.mjs:1705–1728`,
`stubFor()` computes `scoped` but the JS `prep()` function derives `S` and
namespace members from the full `src`. Its JS import enumeration at
approximately lines 1844–1845 also uses full `src`. Method inference therefore
sees all sibling bodies. `references/stubs.md` (#130/#131) explicitly promises
only the requested test's scope.

**Workaround**

Inspect generated stubs and finish/trim them manually, as the documented
compile-not-verified fallback permits. Alternatively place each annotated JS
test in its own file when isolated stub generation is important. The broker's
generated skeletons were manually adjusted for inheritance before Reds.

**Severity:** medium — unexpected out-of-scope file mutation and misleading
per-test stub isolation; does not itself create passing evidence.
