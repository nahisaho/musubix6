## F1. Workspace stubbing cannot create a missing package entry file

**Repro** (run from the musubix6 Git root; minimal fixture is `dogfood-7/findings/repro-app002-1/`):

```sh
cd dogfood-7/findings/repro-app002-1
npm install --ignore-scripts --no-audit --no-fund
node ../../../.github/skills/lean-sdd-tdd/scripts/sdd.mjs --root . tdd stub TEST-STUB-001
test ! -e packages/math/src/index.ts
```

**Actual:** Exit 0, message `no missing relative imports in test/math.test.ts`,
and no `packages/math/src/index.ts`. The test imports `add` from a linked workspace
whose manifest has `"name":"@repro/math","exports":"./src/index.ts"`. Node cannot
load that import because the source entry has not yet been created. If workspaces
have not been linked, the command instead warns that no workspace/tsconfig path
resolves the package, although its manifest is present.

**Expected:** Generate a throwing `add` stub in the manifest-declared workspace
entry, as documented for missing bare workspace imports. At minimum report that
the declared source entry is missing, rather than reporting there is nothing to
stub.

**Location:** `.github/skills/lean-sdd-tdd/scripts/sdd.mjs`, `stubFor` package import
branch / `pkgEntry`, lines 1840–1856; `aliasMap` / `pick`, lines 2307–2330.
`pkgEntry` accepts only non-directory aliases, but `aliasMap.pick` requires the
candidate source file already to exist in `gitFiles`. Thus the exact missing-file
case that stubbing should handle cannot produce a file alias.
Related documentation: `references/stubs.md`, TS/JS workspace-package support.

**Workaround:** Hand-write a typed, loadable scaffold and obtain assertion Reds;
alternatively start with a relative source import that the generator supports.
This app used the first workaround without modifying `.github/`.

**Severity:** med — documented TDD bootstrap support silently fails.

## F2. Subdirectory roots make changed gates skip all workspace tests and evidence

**Repro** (run from the musubix6 Git root; fixture has a deliberately failing
test and no Green ledger record):

```sh
node .github/skills/lean-sdd-tdd/scripts/sdd.mjs --root dogfood-7/findings/repro-app002-2 gate --changed
node .github/skills/lean-sdd-tdd/scripts/sdd.mjs --root dogfood-7/findings/repro-app002-2 gate
```

**Actual:** Changed gate exits **0** and prints:

```text
SDD GATE PASS
✓ trace: 1 REQ, 0 errors
✓ ledger: 0 entries, chain intact
✓ tdd evidence (changed scope): 0/0 tests Red→Green
! cmd pkg:test: no changed files in pkg — skipped
```

The full gate exits **1**, correctly identifying no recorded Green and the
assertion failure `answer() === 1` (implementation returns 0). The main app also
reports changed evidence `0/0` and skips **all five** project checks despite every
application source/test being untracked. It additionally leaks unrelated
parent-repository `.github` paths into its root-owned configuration warnings.

**Expected:** Normalize Git status paths relative to `--root`, filter changes
outside that root, include changed test evidence, and run affected project checks.
The fixture must not pass while its sole changed requirement has no Green and
its sole test fails.

**Location:** `.github/skills/lean-sdd-tdd/scripts/sdd.mjs`, `changedFiles`,
lines 2291–2296; downstream changed-evidence and project-skip logic in `gate`,
around lines 2494 and 2560. `git status --porcelain -uall` returns paths relative
to the **Git top level**, even when invoked with `cwd: ROOT`. The script stores
these verbatim, but compares them against **app-relative** annotation/project
paths. The app-prefix mismatch yields no selected tests and no changed projects.

**Workaround:** Run the full gate (no `--changed`) for nested app roots.
This app's final authoritative full gate passes with 44/44 test evidence,
strict TypeScript checking and all five workspace suites. No script edits or
nested Git repository initialization were used.

**Severity:** high — false PASS bypasses both required TDD evidence and failing
tests in the explicitly supported `--root`/multi-project workflow.
