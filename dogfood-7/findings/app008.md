## F1. Nested `--root` makes `gate --changed` falsely PASS without workspace tests

**Minimal Repro**

Fixture: `dogfood-7/findings/repro-app008-1/`. It records an assertion Red, changes the implementation to pass, records Green, regresses the implementation, and runs both gates. No nested Git repository is created.

```sh
node dogfood-7/findings/repro-app008-1/reproduce.mjs
```

**Actual**

`gate --changed` exits **0**, reports `SDD GATE PASS`, `tdd evidence (changed scope): 0/0`, and skips `packages/worker:test` as having no changed files. The same fixture's full gate exits **1**, with `TEST-NESTED-001` assertion failure (0 instead of 1). The app's initial changed gate similarly skipped all five workspace suites while printing unrelated parent-repository changes.

**Expected**

Git status paths should be rebased to `--root`, and changes outside that root excluded. A changed file at `<nested-root>/packages/worker/answer.mjs` must select that project's tests and evidence; the regressed fixture must fail, not PASS.

**Location**

`.github/skills/lean-sdd-tdd/scripts/sdd.mjs:2291–2295`, `changedFiles()`: `git status --porcelain -uall` emits repository-root-relative paths even when its cwd is the nested ROOT; the function stores them unchanged. Project selection at lines 2553–2567 and changed evidence then compare them against ROOT-relative paths.

**Workaround**

Always run the full gate for a nested `--root`. Do not interpret this changed gate as test coverage. The final app full gate runs typecheck and all five workspace suites successfully.

**Severity:** high — false acceptance of a real implementation regression.

## F2. JS/TS `tdd stub <ID>` edits real code for sibling tests outside the requested scope

**Minimal Repro**

Fixture: `dogfood-7/findings/repro-app008-2/`. The existing real `Worker.run()` passes TEST-SCOPE-001; only sibling TEST-SCOPE-002 calls missing `stop()`.

```sh
node -e 'require("node:fs").writeFileSync("dogfood-7/findings/repro-app008-2/src/worker.mjs", "/** @id CODE-SCOPE-001 @implements REQ-SCOPE-001 */\nexport class Worker { run() { return 1; } }\n")'
node .github/skills/lean-sdd-tdd/scripts/sdd.mjs --root dogfood-7/findings/repro-app008-2 tdd stub TEST-SCOPE-001
cat dogfood-7/findings/repro-app008-2/src/worker.mjs
```

**Actual**

The command reports `stubbed ... src/worker.mjs` and appends throwing `Worker.stop(...)` to the real implementation, even though the requested test never calls it and already has everything it needs.

**Expected**

No edits for TEST-SCOPE-001. Only the shared preamble and requested test body should contribute method inference, consistent with `references/stubs.md`'s scoped-generator guarantee.

**Location**

`sdd.mjs:1708–1729`, `stubFor()` computes `scoped` but JS/TS `prep()` returns `S = src` (the entire file). `jsExisting()` at lines 1825–1837 passes that unscoped text to `methodsOf()` and `staticsOf()`. Relative/dynamic import discovery at lines 1849–1851 also uses full `src`.

**Workaround**

Isolate the requested test in a single-test file before generating stubs, or hand-write a skeleton and inspect the stub diff. The app's incomplete generated Engine skeleton was completed manually as documented.

**Severity:** med — unexpected production-code edits and failure attribution from unrelated tests.

## F3. JS/TS stub generator misclassifies a class inside `assert.rejects` as an Error type

**Minimal Repro**

Fixture: `dogfood-7/findings/repro-app008-3/`. Its test calls `assert.rejects(new Worker().run(), /failure/)`; Worker is the subject under test, not the expected exception type.

```sh
rm -f dogfood-7/findings/repro-app008-3/src/worker.mjs
node .github/skills/lean-sdd-tdd/scripts/sdd.mjs --root dogfood-7/findings/repro-app008-3 tdd stub TEST-WORKER-001
cat dogfood-7/findings/repro-app008-3/src/worker.mjs
```

**Actual**

Generated source declares `export class Worker extends Error`, initializes `this.name = 'Worker'`, and then adds the throwing `run()` stub. The actual app's Engine was also initially generated as `extends Error`.

**Expected**

Generate an ordinary Worker class. Only an expected error constructor in an error-matcher position (or a clearly error-named class) should get Error inheritance, not an arbitrary class used in the expression being asserted.

**Location**

`sdd.mjs:1739`, `exportOf()`: `\\b(...|throws|rejects)\\([^)]*\\b${n}\\b` searches arbitrary text inside the assertion's first expression and interprets the subject class as an expected exception.

**Workaround**

Remove the spurious Error inheritance from the generated skeleton; write typed/synchronous-versus-async stubs manually when necessary. This is a classification defect, not a claim that stub compilation was verified.

**Severity:** med — generated class identity, prototype and constructor behavior are wrong.

## F4. A passing characterization Red is reported as “fails with” a runtime footer

**Minimal Repro**

Fixture: `dogfood-7/findings/repro-app008-4/`; the golden test always passes.

```sh
node .github/skills/lean-sdd-tdd/scripts/sdd.mjs --root dogfood-7/findings/repro-app008-4 tdd red TEST-GOLDEN-001 --characterization 'Golden fixture already passes without production implementation'
```

**Actual**

Exit 0 with output such as `RED ok TEST-GOLDEN-001 ... — fails with: ℹ duration_ms 54.731248 [weak]`. The test did not fail; a benign runner timing footer is presented as its failure reason. The app's TEST-RUNTIME-013/014 showed the same message.

**Expected**

Report explicitly `characterization: test passed without failing Red` (or equivalent), using the supplied reason. Do not claim a failure or invent one from successful runner output.

**Location**

`sdd.mjs:2204`, `tdd()` computes a Red `reason` even when the characterization run succeeded, falling back to the last nonempty output line. The Red output formatting labels that value `fails with`.

**Workaround**

Inspect `exit: 0`, `characterization`, and the supplied reason in the ledger; rely on the gate's separate characterization count rather than the misleading one-line failure wording.

**Severity:** low — misleading evidence presentation, not an incorrect gate verdict.
