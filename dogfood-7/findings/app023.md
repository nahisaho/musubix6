## F1. Fatal Python runner crashes are accepted as strong Red evidence

**Repro**

The persistent fixture is `dogfood-7/findings/repro-app023-crash/`.
From the repository root, run:

```sh
sh dogfood-7/findings/repro-app023-crash/run.sh
```

The fixture disables core dumps, initializes the pytest workflow, and runs
`ORM_CRASH=1 ... tdd red TEST-CRASH-001`. Its implementation calls `os.abort()`
before the assertion can evaluate. Then the same unchanged test runs Green with
the crash environment flag unset, followed by a full gate.

**Actual**

- A direct captured pytest run confirms return code `-6` (SIGABRT), with
  `Fatal Python error: Aborted`; this is a crashed interpreter, not a test failure.
- The workflow prints `RED ok TEST-CRASH-001 ... fails with: <truncated rest of calls>`.
- The ledger records `type: red`, `exit: 1`, and no `weak` classification.
- Green succeeds and the full gate reports `SDD GATE PASS`, evidence `1/1`.

**Expected**

A signal-terminated Python test runner must be rejected as an unknown result,
without writing Red evidence. The documentation states that crashed runners
are rejected, and even an intentional abort is not an assertion Red.

**Location**

`.github/skills/lean-sdd-tdd/scripts/sdd.mjs:492–512`, `run()`, converts a
signal exit (`status === null`) to generic exit 1 and discards `r.signal`.
`cmdTdd()` at line 2177 only recognizes JVM/CLR crash text; it
does not recognize `Fatal Python error` or child process termination signals.

**Workaround**

Inspect fatal interpreter output manually and never accept such a Red. Replace
the crashing implementation with an assertion-failing stub and record a new Red
before implementing the real behavior. Disable core dumps during reproduction.

**Severity:** high — unknown/crashed execution can satisfy mandatory Red proof.
