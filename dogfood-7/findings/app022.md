## F1. A trailing Python oracle helper can change without invalidating Red evidence

**Repro:** A self-contained fixture is in `dogfood-7/findings/repro-app022-helper/`.
From the repository root:

```sh
sh dogfood-7/findings/repro-app022-helper/repro.sh
```

The script records Red for `assert actual() == expected()` where production
`actual()` returns 1 and the test helper `expected()` returns 2. It then changes
only `expected()` to return 1, records Green, and runs the full gate. The helper
is a normal top-level Python function immediately after the annotated test,
inside the same test file. The requirement still requires production to return
2; `production.py` is never changed.

**Actual:** Both runs use the same recorded `fileSha`; `tdd green` prints
`GREEN ok TEST-ORACLE-001` and exits 0. The full gate exits 0 with
`tdd evidence: 1/1 tests Red→Green`, even though the test oracle was changed
between Red and Green and the implementation remains contrary to its spec.
This is not an empty selection, skip, import-alias change, or decorator:
the test actually executes and asserts against a changed local helper.

**Expected:** Hash protection should include helpers actually used by the
annotated test (or conservatively include same-file helper definitions),
refusing Green until a new Red records the changed oracle.

**Location:** `.github/skills/lean-sdd-tdd/scripts/sdd.mjs:52–95`,
`testShaVariant()`: its `cut` loop at lines 77–85 stops at the next top-level
construct; the final hash includes only the test's region and the preamble
before the first annotation. Helpers declared after that annotation are in
neither region. `shaMatchesRaw()` consequently accepts unchanged evidence.

**Workaround:** Put shared test helpers and oracle data before the first
`@id` annotation (then the preamble hash covers them), or inline the oracle in
the annotated test; manually re-record Red whenever a trailing helper changes.

**Severity:** high — falsified Red→Green evidence and a false full-gate PASS
can be obtained by changing test behavior rather than implementing the REQ.
