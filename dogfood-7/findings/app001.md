## F1. Nested --root makes gate --changed silently skip all TDD evidence

**Repro** (run from repository root; fixture included at `dogfood-7/findings/repro-app001-changed/`):

```sh
printf '\n' >> dogfood-7/findings/repro-app001-changed/test.test.mjs
node .github/skills/lean-sdd-tdd/scripts/sdd.mjs --root dogfood-7/findings/repro-app001-changed gate --changed
node .github/skills/lean-sdd-tdd/scripts/sdd.mjs --root dogfood-7/findings/repro-app001-changed gate
```

**Actual:** Changed gate exits 0, reports `SDD GATE PASS`, `ledger: 0 entries`,
and `tdd evidence (changed scope): 0/0 tests Red→Green`. Full gate exits 1:
`TEST-CHECK-001 ... no Green recorded`. The changed test is present and untracked
or modified, not outside the requested app root. In the real three-project app,
the changed gate also skips every package test and emits misleading dependency
hints for unrelated repository files outside `--root`.

**Expected:** Scope repository-relative Git status paths to the requested root,
convert them to app-relative paths, and check the modified test's missing proof.
Changes outside `--root` must not influence project dependency hints.

**Location:** `sdd.mjs:2291–2296`, `changedFiles()`: `git status --porcelain -uall`
returns paths relative to the Git repository root even when its cwd is a nested
app; the returned strings are stored without rebasing/filtering. Gate intersects
those strings with app-relative annotation paths and project roots.

**Workaround:** Always run full `gate`, without `--changed`, for nested app roots.
No app commits or separate Git initialization were used.

**Severity:** high — false PASS bypasses required Red→Green proof and package
checks in the supported nested-root/monorepo workflow.

## F2. Workspace bare-import stubs cannot create a missing exported entry file

**Repro** (fixture included at `dogfood-7/findings/repro-app001-stub/`):

```sh
node .github/skills/lean-sdd-tdd/scripts/sdd.mjs --root dogfood-7/findings/repro-app001-stub tdd stub TEST-STUB-001
test -f dogfood-7/findings/repro-app001-stub/packages/lib/src/index.ts
```

**Actual:** Stub exits 0 with `no missing relative imports in test.test.ts`, then
`! not stubbed: @repro/missing-entry (package import: no workspace package or
tsconfig path resolves it)`. The source existence check exits 1. Its workspace
manifest explicitly names `@repro/missing-entry` and exports `./src/index.ts`.
In the installed real app, npm workspace links made the warning disappear
entirely: the missing entry file still was not stubbed.

**Expected:** Resolve the declared workspace export even before its source
exists, create its parent directory and generate the missing `add` stub.
The docs promise workspace bare imports are stubbed in their entry files.

**Location:** `sdd.mjs:1840–1843`, `pkgEntry()`, and `2307–2341`, `aliasMap()`:
`pick()` only returns a source file already in the Git file set; directory-only
aliases are rejected by `pkgEntry`. Thus missing relative imports are generated
but missing workspace entries are not. Existing package links are mistaken for
usable installed dependencies at `1851–1855`.

**Workaround:** Create the empty declared entry file first, then run `tdd stub`,
or hand-write a throwing typed skeleton (used for the app).

**Severity:** medium — advertised workspace scaffolding fails on the normal
tests-first missing-module case, and can report misleading success.
