## F1. Go external-package stubbing overwrites an existing real `pkg_stub.go`

**Repro**

From the repository root:

```sh
node dogfood-7/findings/repro-app026-overwrite/reproduce.mjs
```

The fixture has module `repro.overwrite`, an external `package pkg_test` test calling missing
`pkg.Missing()`, and an existing production file `pkg/pkg_stub.go` containing the real function
`Keep() int { return 73 }`. It has no generated-stub marker. The reproducer initializes SDD,
runs `tdd stub TEST-OVERWRITE-001`, verifies deletion, and restores the original fixture for repeatability.

**Actual:** `stubbed (throwing, compile-checked): pkg/pkg_stub.go` is reported with exit 0.
The original file is truncated and replaced by `func Missing() int { panic("not implemented: Missing") }`;
`Keep()` and its original comment are lost. The selected test compiles, so no warning exposes the data loss.

**Expected:** Preserve existing user code. Allocate a fresh noncolliding stub filename or append only
to an explicitly identified generated-stub file without discarding its existing definitions.
The documented guarantee “real code is never touched” must apply to Go external-package stubs too.

**Location:** `.github/skills/lean-sdd-tdd/scripts/sdd.mjs`, `stubGo()`, approximately lines 930 and 980:
external targets are always `<package>/<dirname>_stub.go` when production Go files exist, then
`fs.writeFileSync(e.file, render())` writes them without checking existing contents. In contrast,
the in-package branch at lines 904–906 chooses a noncolliding path.

**Workaround:** Back up/rename a pre-existing `<dirname>_stub.go` before stubbing, or hand-write the missing
function in a separate file; restore any overwritten code. Do not trust compile-check success as preservation evidence.

**Severity:** high — deterministic deletion of working production code.
