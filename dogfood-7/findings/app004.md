## F1. Nested --root makes gate --changed silently omit all TDD evidence

### Repro

From the existing Git repository root, using the included untracked fixture:

```sh
node .github/skills/lean-sdd-tdd/scripts/sdd.mjs --root dogfood-7/findings/repro-app004-1 gate --changed
node .github/skills/lean-sdd-tdd/scripts/sdd.mjs --root dogfood-7/findings/repro-app004-1 gate
```

The fixture has one T1 REQ, annotated implementation and passing test, but
intentionally no Red/Green ledger. Do not record TDD evidence for this fixture.
If the fixture becomes committed, change its requirement/test before reproducing.
An explicit staged or unstaged change under a nested root has the same path mismatch.

### Actual

`gate --changed` exits **0** and prints:

```text
SDD GATE PASS
✓ trace: 1 REQ, 0 errors
✓ ledger: 0 entries, chain intact
✓ tdd evidence (changed scope): 0/0 tests Red→Green
✓ cmd test
```

The full `gate` correctly exits **1**, reporting:
`TEST-NESTED-001 (REQ-NESTED-001): no Green recorded`.
The actual app's changed gate likewise reported `0/0` while its full gate checked
all 40 (subsequently 45) annotated tests.

### Expected

The changed gate must include the changed nested-root test and requirement, and
fail for missing TDD evidence just like the full gate. The brief explicitly
requires app-local `--root`, so this affects the intended workflow directly.

### Location

`.github/skills/lean-sdd-tdd/scripts/sdd.mjs:2291–2296`, `changedFiles()`.
`git status --porcelain -uall` returns paths relative to the Git worktree root,
even when invoked from the configured nested `ROOT`. Its paths are inserted
unchanged into the set, but entities and file existence checks are relative to
the nested app root. `git ls-files`, used for entity scanning, supplies app-relative
paths, causing the mismatch.

### Workaround

Run the **full gate** for app-local roots; do not trust changed-scope evidence.
No `.github/` files were modified. Both full and changed gates, JS stub generation,
weak Red attribution/`--expect`, spec edits after Green with stale lock refusal,
AI relocking, cross-feature impact, and refactor evidence were exercised.

### Severity

**high** — a missing-evidence change receives a successful gate verdict.
