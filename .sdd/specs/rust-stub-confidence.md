## Design
Keep the existing concrete i64 placeholders for compatibility, but label them rather than claiming evidence. An integer literal comparison is supported inferred evidence, not the unsupported i64 fallback. Restrict receiver masking to Rust identifiers rather than numeric digits: the current word-character pattern erases 0. in 0.5. This repairs existing float-literal inference rather than adding a new inference grammar. Record inherent methods as Type::method with the method's actual test line; distinguish known return evidence/constructor/builder rules from the final i64 fallback. Share existing report and marker conventions.
Reuse stubTodoHit and its compile-only call site. An independent review exposed a native same-name counterexample: marked method value was blamed for unrelated let value:u8=true. Attribute Rust functions through an actual call in masked compiler source excerpts or the marked declaration's exact location, not arbitrary help text, quoted strings or same-named variables. Preserve fn-block extraction and existing-member insertion with inline marker comments, without duplicating markers.
Finite rows: function return={supported,unknown}; inherent method={supported,unknown,constructor,builder,compiler-discovered addition}; constant={annotated,literal,loop-only,unknown}. Cross marked compiler refusal with flags={plain,weak,expect}. Check report and no-report diagnostic paths.
Risk stages: contract=explicit placeholder/report rules; trusted inputs=test-owned shape evidence, not an inferred claim from missing types; execution=native offline cargo and bounded subprocesses; verdict=reject marked compile errors but accept runtime Red/Green; history=no evidence on refused runs, genuine new regression Red/Green; integration=canonical shared payload, real package/host checks and root full gate. No stage is inapplicable.
