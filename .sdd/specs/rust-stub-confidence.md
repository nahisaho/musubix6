## Design
Reuse the current inference and diagnostic boundaries. Do not guess Result payloads from `.ok()` or bool tuple types from loop bindings alone. Preserve unsupported fallback declarations for compatibility, but put markers on the same declaration line. Report qualified method names with a real test evidence line. Resolve comparison evidence through receivers of the owning type, reusing supported first/reverse assertion arguments and ordinary equality; message arguments are not type evidence. Existing-type member additions remain marked manual repairs. Marked uncompilable fallback plus named repair guidance satisfies the fallback contract; it never establishes ordinary Red. Do not change native compiler verdicts, weak overrides, budgets, versioned release evidence, report/ledger schemas or other languages.

Follow-up scope approved by the user: explicit Result<bool, E> types, boolean scalar/tuple loop elements and owner-specific method arguments. For Result aliases, accept only the immediately adjacent typed assignment of a binding holding the whole call, not a transformed return or a later/shadowed binding. Reuse written types rather than synthesize an error type. Direct annotated function calls retain shown reporting; method rows retain their existing inferred reporting. For loops, collect direct assert_eq!/assert_ne! (both orders) and ==/!= literal evidence within balanced loop bodies; infer only when every binding in every loop for that constant has exclusively bool evidence. Reject shadowed bindings conservatively. Unknown/numeric loop inference remains outside this extension. Reuse the same owner receiver pattern for method return, arguments and empty-collection constraints; associated-call qualification and generic fallback parameters remain unchanged. No Rust overload support or arbitrary alias/dataflow analysis.

The directly dependent release-helper fixtures must use the historical approved Git revision, not pretend that later development bytes match the old inventory. Archive `vendorReference.sourceCommit`, retain all original source/package/path/mode controls, and overlay the unchanged locked content reference outside the npm payload. Every workflow test job calling `npm test` needs full checkout history (`fetch-depth: 0`): `.github/workflows/ci.yml` and the test job in `.github/workflows/publish.yml`. The publish-only job remains unchanged. Local shallow-history archive fails with exit128, restored full history archives with exit0 and matches all approved source inventory bytes/modes. This is fixture-provisioning spike evidence, not assertion Red, hosted Actions evidence or publication authorization.

Six failure stages: contract—unsupported types presented as evidence-backed; trusted inputs—assertion position, loop scope, adjacent written type and receiver ownership must belong to actual test usage (the first violated condition for the new alias/loop/arity risks); execution—native Cargo compile controls, not CLI text alone; verdict—compile failures never ordinary Red; evidence history—refusal preserves ledger bytes; integration/distribution—full regression and supported Node runtimes, with no new release or npm publication claim. None of these stages is inapplicable.
