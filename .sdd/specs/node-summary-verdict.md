Ten finite rows: each of spec/TAP with all-pass (exit 0), mixed pass/fail (1), all-fail (1), all-skipped (2), and no registered owned test (1). The final control must fail the existing required-test ownership contract: Node can count the empty file itself as passing, but the gate must not borrow that result for its required test. These are bounded native registration/verdict states, not an exhaustive test of arbitrary reporter text. Assertions use real Node execution and contract-defined expected exits; neither output from the implementation nor its classifier defines the oracle.
Risk stages: contract=failed executed checks must fail; trusted inputs=native reporter text and actual exit; execution=real isolated fixtures; verdict=positive executed counts take precedence over zero-test phrases in titles; evidence history=real Red/Green, no fabricated execution; integration=the repository's 1084-test run exposed the misclassification while three stale literal self-checks failed.
## Design
Extend the existing positive-execution recognizer with anchored positive Node spec/TAP pass/fail summary lines. Do not change ownership, skip/TODO, malformed-total admission, timeout rules, or any native success checks.
Only the no-test fallback classification changes; a fabricated positive line cannot turn an unsuccessful process into PASS.
For v0.2.8 observability, prioritize anchored failing result rows and assertion/error records after removing successful spec/TAP result rows. Keep other ecosystem failure hints as a fallback, bound each emitted line to 1024 characters, and leave the verdict/retry classifier unchanged.
Retain the original captured process buffers before decoding their existing combined diagnostic text. Each gate-check attempt gets a unique directory under `.sdd/check-output/`, separate `stdout.log` / `stderr.log`, and a JSON receipt with SHA-256 and byte counts plus native outcome metadata. Do not retain argv or environment. Existing 64-MB process capture limits still apply and must be identified, never called complete unbounded output.
Create the output parent with POSIX mode 0700 and files with 0600/exclusive creation; reject symlink/non-directory parents and non-private existing output directories on POSIX. Windows inherits directory ACLs; POSIX mode checks are not a Windows ACL guarantee. An internal `.gitignore` ignores every output entry, including itself, even in projects not initialized by this checkout. No upload, automatic deletion or approval is performed. Retention errors stop the check/retry path with an explicit gate failure; previous attempts remain untouched.
The six first-failure stages for this change are: contract = retain every captured attempt, not only the eventual verdict; trusted inputs = reporter text is diagnostic-only and storage symlinks/non-private parents are refused; execution = preserve native byte buffers and timeout/limit/signal metadata, including partial output; verdict = fail-then-pass remains FAIL by default and valid passing checks stay accepted; evidence history = immutable unique attempts with byte hashes, never replacing the original failed release evidence; integration/distribution = packaged native/wrapper operation must contain this same monolithic implementation, and local raw logs must not enter commits or npm payloads.
## Assumptions / limits
This regression covers two supported native reporters and one test-title collision, not every third-party reporter. Existing native ownership/skip tests and the complete root gate remain required. The interrupted 30-minute run and the subsequent failed/incomplete runs are not passes or release qualification.
Issue #385 contains two separate problems: deterministic observability defects and an unreproduced intermittent failing assertion. Fixing retention/summary does not identify or resolve that assertion, close the issue, waive its acceptance criteria, or grant qualification/publication credit.
