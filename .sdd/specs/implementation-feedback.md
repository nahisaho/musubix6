## Design
Add a zero-dependency helper and `feedback status [FEATURE]` / `feedback record FEATURE`; status is read-only. Inventory is the existing configured native source scan plus explicit implementation-task artifacts, before task-scope filtering. Exclude `.sdd/` execution state/specifications, documentation-only task artifacts and TEST-only native files with no CODE annotations; unannotated source files are not implicitly tests. Every remaining file needs implementation-task ownership and each CODE/REQ reference must agree with that ownership. Scan filters are trusted project policy, not proof about excluded/unsupported files; policy weakening still requires existing human approval rules.
The canonical spec contains fenced `sdd-feedback` JSON objects with exactly `schemaVersion:1`, feature-local lifetime-unique `id`, `implementationSha256`, nonempty `summary`, `reqs` and `tests`. Digest is SHA256 of JSON.stringify(rows), ordered by path, with each row `{path,sha256,owners}` and each owner `{feature,task,reqs,codes}`; owners sort by feature then task, IDs sort lexically, and shared paths bind every owner. Record requires the newest entry to match that digest, cover current and previously accepted affected REQs with existing mapped TEST references, and retain every accepted entry unchanged and in order. Validate live REQ/TEST references at both recording snapshots even for idempotent success; a restored valid mapping preserves idempotence, while loss/recovery during acceptance must not establish success. Summary is the mandatory design/change note, not a semantic attestation; no baseline or prose is synthesized.
History is bounded append-only hash-linked `.sdd/spec-feedback.jsonl`, serialized by a non-stealable directory lock: 8 MiB history, 1 MiB canonical record/spec, 4096 records/source paths, 64 MiB cumulative source hashing and the configured per-source scan cap (16 MiB default). Each row binds the entire spec hash, accepted entry identities and current feature source/ownership snapshot. Only the latest row for a feature counts; A-to-B-to-A needs a fresh entry ID. Compare prior/current ownership before scope filtering: deleted/renamed paths and transfers require updates from previous and current owners; a successful removal stores the new empty/current snapshot so former owners do not own future changes forever. Rows retain outgoing same-path `transfers` as complete receiving `{path,sha256,owners}` identities and `acknowledges` as sorted unique SHA256(JSON.stringify([origin-record-hash,transfer-index])) IDs; validate prior ownership, loss of ownership, recipient membership and earlier unresolved token references. A former owner's empty snapshot alone must not release a pending counterpart. A recipient can acknowledge with a fresh entry covering the transferred REQs even if its current snapshot is now empty; an exact receiving source/ownership acceptance after the former owner's last owning row also counts when recorded first. Resolved transfers do not reattach former owners to future recipient edits. Keep canonical former owners and affected REQs resolvable through this transition; feature/spec/REQ retirement itself is not added by this feature and unresolved retirement blocks with 2.
States/exits: disabled or current=0; missing entry/acceptance, unresolved mapping/configuration/planning, malformed history or occupied lock=2; a previously accepted source/spec/ownership identity that changed=1. Verify and full/changed gate use their effective tasks/prerequisites plus affected former/shared owners; unknown inventory mapping and malformed history block before narrowing, including empty changed-task scopes. Revalidate source/spec/ownership/history immediately before recording and after task checks before any successful receipt; compare global inventory/history at both gate boundaries without permanently binding unrelated history to every task receipt. Preserve native TDD, approval, dependency and history checks; Red/Green remains available. Acceptance proves identity consistency, never semantic correctness, test success or release readiness.
