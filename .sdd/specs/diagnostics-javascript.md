## Design
既存ESLint providerのロード・診断変換を共有し、入力選択だけをprofileで分ける。TS側のtsconfig選択は変更しない。
includedは列挙したJS候補、ignoredはESLintが除外/未設定とした候補、checkedは有効lint結果を得た候補。壊れたsymlink・読取失敗・不正結果は未完了にする。

Repository configuration addition (2026-10-23): use pinned direct development dependencies `@eslint/js` and `globals`, the recommended rules unchanged, Node globals, JSX parsing, and `noInlineConfig:true`. No new automatic gate step, consumer configuration or provider semantics. The user selected fixing all 102 existing findings rather than warning downgrades. Use ESLint's mechanical fixes where available; remove unused bindings without removing evaluated side effects; preserve deliberate recovery catches with explanatory comments; replace control-character regexes with equivalent literal operations or Node's ANSI utility. Re-run affected semantic tests and refresh evidence for edited registered test bodies.

Repository risk stages: contract=all recommended rules remain error; trusted inputs=only root-local pinned packages/config, no exclusions hiding .github; execution=trusted config, no fix/cache during diagnosis; verdict=valid0, lint/parse1, missing/ignored config2 controls; evidence history=append real Red/Green, never rewrite prior ledger, record mutations separately; integration/distribution=config remains repository-only and existing init/pack behavior must remain unchanged.
## Assumptions / risks
Directory symlinkを追わず、file symlinkは実体が読める通常fileのみ許可する。root外の実体は共通契約の絶対pathで表示する。候補拡張子は大文字小文字を区別せず、ESLint設定の適用結果はそのまま尊重する。
