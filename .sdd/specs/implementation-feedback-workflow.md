## Design
Lean SDD/TDD owns the complete loop; lean-agentic-coding delegates to it rather than creating another requirements file or acceptance format. Extend the existing canonical specifications, not parallel requirements documents.
Loop: implementation delta -> requirement/design impact review -> canonical design/change entry -> genuine required review/approval -> current plan bindings -> native tests and restored mutations -> explicit feedback record -> refresh affected bindings/prerequisite verification -> task verification. Acceptance changes completion fingerprints; pre-record previews can be stale. Canonical impact review/change notes apply to every batch; CLI acceptance steps apply only when feedback is enabled, otherwise retain existing approval/TDD/gate without recording or silently enabling it. Repeat affected stages after any relevant change; Red/Green remains available while completion is blocked. Both READMEs clarify that intentional legacy opt-out also disables enabled feedback.
Use bounded source and actual package/both-host controls. Tests of distributed instructions establish their presence and consistency, not arbitrary future model obedience. No watcher, scheduled autonomous task, release validation, tagging or publication is authorized by this feature.
