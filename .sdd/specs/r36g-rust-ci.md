## Design
Introduce one Rust-local Cargo wrapper returning normalized text plus status, signal, and spawn error. It retains the existing 120000ms timeout and environment, strips ANSI SGR once at the piped Cargo diagnostics boundary, and preserves cargo test --no-run --offline --test <requested filename>. Do not pin color to never. All Rust consumers use that wrapper: the initial preOut probe, names, variants, notes, iterative member-growth probes, and final compile witness. Keep shared probe and other languages unchanged; preserve source generation, original tests/names, and the zero-dependency single-file implementation.

The final witness must satisfy status === 0, no signal, no spawn error, and no parsed compiler error (including terminal error: could not compile). Otherwise choose the actual compiler diagnostic, then explicit spawn-error, signal, or exit-status fallback; empty/unparseable text is never evidence of success. Do not change generation scope or treat compiler presentation as a capability issue. Inputs include both test bodies, cfg(test) module, and undefined macro. No runtime/test isolation or shared environment changes; regressions pass per-child environments. No data/history policy changes, installer or Python edits.
## Feasibility and severity
S2 production/public-contract false compile verdict, not a defective test assumption or missing toolchain: hosted dtolnay/rust-toolchain sets CARGO_TERM_COLOR=always; local and hosted rustc 1.99.0 match. stubRust's anchored /^error/ extraction reads colored output from probe unchanged (sdd.mjs:2766,2841-2844). Shared probe additionally drops status/signal/error, so normalization alone cannot establish an actual successful compile. Native Cargo exits 101 and independent rustc exits 1 for both exact invalid emitted fixtures; the three valid fixtures compile with both tools. The previous expected failures are valid: an unrequested unresolved import remains in the compiled test file, and an undefined macro is a compile error. cfg(test)-only double does not satisfy the integration import; the generated public double does.
