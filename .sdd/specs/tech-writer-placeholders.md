# Context-aware placeholder detection
Goal: reduce both false positives and missed markers without introducing dependencies or a publication gate.
| ID | EARS requirement | Test |
| --- | --- | --- |
| REQ-TW-PH-001 | When linting prose, the linter shall detect TODO/FIXME/TBD/XXX case-insensitively with optional horizontal whitespace before ASCII/full-width colons, report empty/unclosed parenthesized annotations, and accept nonempty annotations; unpunctuated lower/title/mixed-case todo in ordinary prose shall remain accepted. | TEST-TW-PH-001 |
| REQ-TW-PH-002 | When scanning for placeholders, the linter shall ignore inline code with matching backtick runs, fenced code, URL tokens, inline Markdown link destinations and compound identifiers joined by hyphens, dots or path separators, without hiding link labels or unresolved markers elsewhere on the same line. | TEST-TW-PH-002 |
| REQ-TW-PH-003 | When initializing tech-writer from source or a packed package, the installed linter shall preserve these classifications, advisory exit 0, JSON finding fields and missing-input exit 1. | TEST-TW-PH-003 |

Oracle: explicit lexical policy above, not the linter's own output; enumerate every ASCII case variant (16 `TODO` + 32 `FIXME` + 8 `TBD` + 8 `XXX`), gaps empty/space/tab, and colons U+003A/U+FF1A. Tracking annotations allow an optional gap and immediate ASCII parentheses with non-whitespace content; URL/path/code annotation contents must remain nonempty after context masking.
Risk stages: contract — preserve advisory interface and the #233 lower-case name exception; trusted inputs — mask only recognized token ranges, never the rest of a line; execution — stdlib Python and installed helper, no network/dependency addition; verdict — assertion Red and both positive/negative controls; evidence history — retain actual logs and isolated mutation/restoration results, never reuse old qualification; integration/distribution — run source, real init and extracted-package tests.
Limits: lexical heuristics, not natural-language intent or a complete CommonMark parser; lowercase `todo finish this` without punctuation stays ambiguous/accepted (use a colon or uppercase marker); uppercase natural-language app names should use code formatting or a compound identifier. Only single-line code spans and inline Markdown links are recognized; reference links, nested link destinations and list-container code parsing are not added. Nonempty annotations remain accepted without validating ticket existence or reason quality.
Provenance: this is a subsequent local improvement to #233, not an upstream resync. The previous kotonoha merge's frozen lint hash and mutation evidence remain historical; this new tree has no release-qualification credit.
