## Design
`evaluateImplementationPlan` consumes the validated model plus existing trace/ledger adapter. Precedence: stale spec/definition/dependency binding or such prerequisite→replan-required; matching bindings but stale/missing verification after ANY on-disk attempt or complete claim→revalidation-required; other incomplete prerequisite/authored blocked→blocked; valid current receipt and complete prerequisites→complete; otherwise authored in-progress→in-progress, else not-started. History is discovered on disk, never from authored receipt/status: clearing receipt or changing status cannot hide an attempt. A newer failure or receipt/head mismatch remains revalidation-required/FAIL1. Absent required files/evidence is INCOMPLETE2; conclusive mismatches FAIL1. Neither claim nor hash refresh completes.
Task-input SHA256 binds definition, actual spec/artifact bytes, recursive dependency fingerprints and current verification commands; excludes status/receipt paths and aggregate gates. `plan verify TASK` explicitly runs checks/native TDD, checks inputs before/after, then exclusively writes immutable success/failure receipts with command/exit/log hashes and selected ledger-event hashes in `.sdd/plan-evidence/<sha256(UTF8(task-id))>/`; hash-derived names prevent Windows case-fold/reserved-name collisions without changing logical IDs. Per-task chains have one latest head; authored receipt must name that current success, so clearing/changing it never restores an old pass. Broken/branching/unparseable history refuses; bounded4096receipts and cumulative64MiB per evaluation, selected tasks/prerequisites only for scoped stages. It prints the path; only the agent edits the plan. Missing/tampered logs, stale inputs or nonzero/signal/timeout refuse completion; local evidence is not hostile-host attestation.
Documentation tasks may own only .md/.rst/.txt/.adoc files and require explicit argv checks; implementation tasks require referenced TESTs and current existing TDD evidence. Verification uses actual native execution/selection guards, not arbitrary supplied exit0. Receipt/output1MiB/8MiB limits and per-check timeout1..600000ms; no implicit gate or installation. Preserve every failed attempt, existing ledger and honest characterization/Refactor warnings; finite precedence combinations and bounded dependency graphs are required tests, not mechanical test-quality guarantees.
The shared evaluator exposes task fingerprints and the independently specified precedence above. Missing future output artifacts are represented as null in an unattempted task's fingerprint, not as completed work; verification requires those artifacts to exist. An implementation adapter supplies current native TEST/command bindings, existing evidence verdicts and selected ledger-event hashes, and explicitly reruns each declared native TDD verification. Missing adapters never imply success. Receipt-event membership must remain valid in current native evidence; unrelated ledger appends do not change fingerprints. A new task's missing evidence is legitimate pending work for consistency, never a successful gate.
Receipt schema1 binds task ID, sequence, previous receipt digest, definition/input SHA256, verdict/exit, literal command results and log hashes, selected native ledger events and explicit errors. Each immutable JSON filename is its complete UTF-8 byte SHA256; the unique sequence1..N chain must start with an empty predecessor and have no fork, gap or orphan. Logs remain below the task's hash-derived directory and are included in the cumulative read budget. A changed artifact needs revalidation; changed definition/spec/dependency bindings need replanning. An authored reference must equal the unique current successful receipt. A missing referenced receipt/input is INCOMPLETE2, a missing/cleared reference after an observed attempt or a conclusive binding/log/history mismatch is FAIL1, malformed evidence is INCOMPLETE2. Explicit verification preserves a failure receipt even for a missing artifact, unsuccessful native preflight, nonzero check or changed before/after inputs. No command silently edits authored status or bindings.
Concurrency is unsupported and explicitly refused: acquire an exclusive per-task verification lock before execution or sequence assignment, hold it through the immutable write, and release it in finally. An occupied/abandoned lock is INCOMPLETE2; never steal it based on age. Recovery requires the user to confirm the owning process is absent and remove that exact lock; independent tasks remain usable. This is refusal of multiwriter execution, not coordination/merging support.
Limit policy: receipt-read, cumulative-read and receipt-count overflow are INCOMPLETE2, never truncated success. At 4096 retained receipts, refuse new verification before executing or altering history; no automatic pruning/rollover. Receipt metadata is size-checked before execution; if it cannot fit, retain a small INCOMPLETE2 refusal receipt when capacity permits, with no executed checks. An output overflow terminates the owned command, retains at most the 8MiB captured prefix with an explicit truncation error and writes an INCOMPLETE2 receipt. Failure-receipt overflow or I/O failure is an explicit incomplete persistence error, never a successful verification. Capacity exhaustion requires explicit reviewed replanning/recovery retaining the old history.
Tie rules for the finite oracle: a non-null reference to a nonexistent receipt is always INCOMPLETE2 even when other history exists; a null reference after any on-disk attempt is FAIL1. A complete claim with no history is revalidation-required/INCOMPLETE2. After structural staleness has been considered, a missing owned artifact is INCOMPLETE2 for attempted/claimed completion, while an existing artifact with changed bytes is FAIL1. Legitimately unattempted tasks can remain pending with missing future artifacts. Unparseable history cannot establish bindings or completion.
Pre-execution capacity/busy-lock refusals are returned INCOMPLETE2 without a receipt and without executing checks; they are not recorded execution attempts. A compact refusal receipt is permitted only below the same 4096 cap. The lock is outside the receipt chain, within the exact task-ID hash directory, and binds its task ID/owning process; recovery must target that exact lock, never another task's. Existing-but-changed artifacts yield revalidation-required/FAIL1; missing artifacts yield revalidation-required/INCOMPLETE2 after structural-staleness precedence.
Any refusal that actually writes a receipt, including compact metadata-overflow refusal, counts as an on-disk attempt for history-derived invalidation. Only a refusal with no receipt is outside that rule.
Native preflight retains conclusive fail1 instead of changing it to unknown2. An unavailable TEST binding is unknown, not a measured fingerprint mismatch: preserve incomplete2 and do not use its partial fingerprint to manufacture conclusive prerequisite staleness. Failure receipts may retain deterministic partial input hashes, but those hashes cannot establish current dependency bindings or completion.
## Assumptions / risks
Task-level evidence is not a full-project gate, release qualification or human publication approval. Preserve existing approval policy; history tamper resistance is limited to the existing ledger and Git contracts.
State semantics are covered by TEST-PLAN-STATE-001/004 and finite enumeration. STATE003 uses an injected adapter and actual selected Node checks; native ledger/runner integration is covered separately by CLI tests, not established by these unit tests.
Whole-file hashing is deliberately conservative: even a typo changes every task bound to that spec file; different REQs in the same file are not considered unrelated. Unrelated means outside the spec-binding/dependency closure; TEST-PLAN-STATE-002 pins this boundary.
