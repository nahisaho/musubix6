## Design
`evaluateImplementationPlan` consumes the validated model plus existing trace/ledger adapter. Precedence: stale spec/definition/dependency binding or such prerequisite→replan-required; matching bindings but stale/missing verification after ANY on-disk attempt or complete claim→revalidation-required; other incomplete prerequisite/authored blocked→blocked; valid current receipt and complete prerequisites→complete; otherwise authored in-progress→in-progress, else not-started. History is discovered on disk, never from authored receipt/status: clearing receipt or changing status cannot hide an attempt. A newer failure or receipt/head mismatch remains revalidation-required/FAIL1. Absent required files/evidence is INCOMPLETE2; conclusive mismatches FAIL1. Neither claim nor hash refresh completes.
Task-input SHA256 binds definition, actual spec/artifact bytes, recursive dependency fingerprints and current verification commands; excludes status/receipt paths and aggregate gates. `plan verify TASK` explicitly runs checks/native TDD, checks inputs before/after, then exclusively writes immutable success/failure receipts with command/exit/log hashes and selected ledger-event hashes in `.sdd/plan-evidence/<sha256(UTF8(task-id))>/`; hash-derived names prevent Windows case-fold/reserved-name collisions without changing logical IDs. Per-task chains have one latest head; authored receipt must name that current success, so clearing/changing it never restores an old pass. Broken/branching/unparseable history refuses; bounded4096receipts and cumulative64MiB per evaluation, selected tasks/prerequisites only for scoped stages. It prints the path; only the agent edits the plan. Missing/tampered logs, stale inputs or nonzero/signal/timeout refuse completion; local evidence is not hostile-host attestation.
Documentation tasks may own only .md/.rst/.txt/.adoc files and require explicit argv checks; implementation tasks require referenced TESTs and current existing TDD evidence. Verification uses actual native execution/selection guards, not arbitrary supplied exit0. Receipt/output1MiB/8MiB limits and per-check timeout1..600000ms; no implicit gate or installation. Preserve every failed attempt, existing ledger and honest characterization/Refactor warnings; finite precedence combinations and bounded dependency graphs are required tests, not mechanical test-quality guarantees.
## Assumptions / risks
Task-level evidence is not a full-project gate, release qualification or human publication approval. Preserve existing approval policy; history tamper resistance is limited to the existing ledger and Git contracts.
State semantics require TEST-PLAN-STATE-001/004 and finite enumeration before implementation; evidence interoperability requires TEST-PLAN-STATE-003. No tests, Red/Green or mutation results are claimed yet.
Whole-file hashing is deliberately conservative: even a typo changes every task bound to that spec file; different REQs in the same file are not considered unrelated. Unrelated means outside the spec-binding/dependency closure; TEST-PLAN-STATE-002 pins this boundary.
