## Design
Use `.sdd/config.json` `planning:{required:true,features?:string[]}`. Absent planning or required:false disables without reading the plan; present required must be boolean. Enabled keys=required/features with unique nonempty valid scope IDs: malformed→1, unknown scope→2. Malformed config never implies disabled. SchemaVersion1 has only features[{id,dependsOn}] and tasks[{id,feature,kind,reqs,dependsOn,artifacts,condition,tests,checks,specs,dependencies,status,receipt}]. Checks={name,argv,timeoutMs}; specs exactly maps referenced REQs' owning spec paths→SHA256; dependencies exactly maps effective prerequisite IDs→current task-input SHA256 fingerprints, as evaluated by the evidence/CLI stages, not definition hashes. The structural model validates binding shape/key coverage without claiming input currency or completion. Task REQs belong to one feature; lists are duplicate-free. Implementation tasks list the complete required TEST union; every referenced REQ needs nonempty resolvable metadata tests (missing→2, omission/extra→1), including testOnly/deferred REQs if tasks still reference them. Documentation tasks may list an empty or resolvable subset of TESTs, exempt from union/nonempty-metadata rules, but always require explicit checks. CLI metadata unions spec-forward/native annotated TEST mappings. Kind=implementation/documentation; status=not-started/in-progress/blocked/complete (claim only); receipt=null or in-root path. Reject unknown fields/types/empty scope. Forward-slash relative paths exclude empty/dot/parent segments and POSIX/Windows absolute forms; existing ancestors/regular files resolve in-root. Future files allowed; canonicalize aliases for ownership, not authored definition hashing.
`loadImplementationPlan({root,config,specs})` consumes trusted existing spec records {path,feature,reqs:[{id,tests,deferred,testOnly}],dependsOn?:string[]} and returns {enabled,stage,status,exit,errors:[{id,reason}],model}; model exposes scope/exclusions, tasks with effectiveDeps/requiredTests/definitionSha256, and owners[canonical-root-relative-path]→sorted IDs. Read-only structure accepts stale well-formed bindings for evaluation. Spec frontmatter dependsOn owns mandatory feature edges; JSON may add but not remove. Scope and effective task prerequisites use the full transitive feature closure, including across features with no tasks; union explicit task edges, never display order. Cycle errors identify blocked IDs, not necessarily every actual cycle member. Definition SHA256 is UTF-8 compact JSON.stringify with exact ordered keys id,feature,kind,reqs,dependsOn,artifacts,condition,tests,checks,specs: UTF-16 code-unit sorts for lists and [spec-path,hash] pairs; retain authored paths; preserve check/argv order but check keys normalize to name,argv,timeoutMs; exclude status/receipt/dependency bindings.
Limits: plan1MiB,256features,2048tasks,16384expanded edges,128-character ASCII IDs,64lowercase-hex hashes; each bound accepts equality, rejects excess; other independent constraints still apply. Exact16384-edge valid JSON is unreachable under1MiB because its mandatory64hex dependency entries alone require at least70bytes/edge; test that predicate's boundary separately, never claim whole-plan acceptance. Bound regular-file JSON reads; no external dependency. Independent Python vector `v027-definition-reference.json` pins definition45927d32…. Native Node20/22/24 TDD/ledger/SHA256/exclusive-receipt spike passed; Windows/macOS untested. Scratch Node20 error-format matcher failed first, then corrected; no feature Red credit.
## Assumptions / risks
Single-writer local files; no Issue sync, external service, automatic migration or new mandatory dependency. Git retains authored revisions and existing evidence is preserved; concurrent editing is out of scope, not a safety guarantee.
Project configuration is a trusted policy input: narrowing configured scope or disabling planning requires visible policy review, not a plan-only edit. Preventing an actor from rewriting configuration/Git history is outside this local tool's guarantees; disabled mode does not imply planning passed.
