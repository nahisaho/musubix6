## Design
Keep .github/skills as the single canonical payload; copy unchanged bytes into host-selected roots, with no generated host-specific variants. Parse/validate the complete init request and watchdog policy before any mkdir/copy; do not promise rollback on filesystem failures.
Policy: copilot supports all 10 skills; claude supports all except watchdog; both is their union with per-host filtering. Explicit incompatible selection fails before applying skip/force. Default list stays unchanged; installed/skipped messages identify host paths.
Use skill-relative placeholders and host-native question tools (Copilot ask_user / Claude Code AskUserQuestion); if unavailable, obtain explicit user confirmation in conversation and stop before approval recording. Do not introduce fake tool shims or auto-approve.
For #382, keep a self-contained host-default table in each of the two development skills and refer to it from the operational steps and guardrails. Copilot's development model remains GPT-6.1 Sol; Claude Code uses its configured available Claude model. Explicit requested-model overrides take precedence, but unavailable requested models must be reported and substitution approved rather than silently invented. Do not add a new requirement for separate-model PASS/counterexample authoring; retain all existing independent-review, approval, Red/Green and mutation obligations. Attribution follows the active host's configured defaults/explicit overrides, with the Copilot trailer scoped only to Copilot and no invented Claude identity. Context reset is a suggestion at a safe boundary with the handoff retained, never an automatic reset. Canonical and installed shared trees remain byte-identical; no CLI host rewriting or other skills' behavior changes.
Release cutover changes only the version-bound requirement/oracle and consistent metadata/docs, not the host support policy. Keep prior version history; never substitute a prerelease or an already-published version for 0.2.4. Publication remains separately governed by docs/design-sdd-hardening.md section 3.5.
