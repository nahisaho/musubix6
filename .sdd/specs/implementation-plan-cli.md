## Design
Default to `planning.required:true`, including existing unset projects; optionally set `planning.features`. Only explicit boolean false selects legacy behavior. New init writes true; existing config bytes are retained. The model contract's v0.2.8 finite table and six-stage counterexamples apply to TEST-PLAN-CLI-007, including new init/direct/wrapper, valid plan acceptance, absent/malformed plan refusal and partial/lone distribution. `plan` and `plan check` provide read-only consistency/state plus current fingerprints, with `--json` parity; `plan verify TASK` is the only explicit execution/receipt-write operation and does not edit the plan. Human/JSON results contain stage, planning-enabled flag, status, exit, IDs, reasons and derived states; unsupported arguments refuse rather than silently selecting another stage. New plan shapes accept only `--root`, `--json` and `--help`; usage refusals are incomplete2. Disabled bare `plan`, context and gate retain legacy outputs; disabled `plan check` reports DISABLED, and disabled `plan verify TASK` refuses2 rather than claiming execution.
Load the same JSON feature/task graph for context and gate; enabled context ignores Markdown and retains full-file selection/bounds. Gate uses existing relevant REQs plus changed artifact ownership, reaches all owners and task prerequisites, rejects every unresolved changed input except the known ledger/approval/receipt bookkeeping outputs; plan/config changes conservatively reach the configured scope. Retain all existing checks/approval rules; no-run remains INCOMPLETE. Tasks cannot use their own aggregate gate to create completion evidence.
Consistency checks all stale bindings/derived states but accepts legitimate not-started work; scoped gate checks global structure and only reached-task current completion, not stale dependents outside that selected/prerequisite closure. Such dependents stay stale and block consistency/full gate, not this narrower stage; a fixture must pin this distinction. Full gate checks every effective-scope task. Valid disabled mode preserves legacy outputs/exits/context. Prior native TDD shapes passed Node20/22/24 scratch spike; new command/installed-host shapes still require tests.
Native adapter: union forward spec TEST references with actual native annotated TEST mappings, retain frontmatter prerequisite features, and use the existing trace/approval/evidence verdicts. Bind each required TEST to its current native hash, required REQ hashes, configured runner/project, and distributed CLI module bytes; selected ledger-event hashes are separate from that fingerprint. Every completed implementation verification reruns `node <actual-installed-sdd> tdd refactor <TEST>` through the existing hermetic executable/environment resolver, with an explicit bounded output/error channel. Preflight must already satisfy current native evidenceStatus before any declared check or native rerun: plan verification cannot itself bless a changed T2 test through refactor. Missing Green/preceding Red or missing required TEST/approval is incomplete2; stale TEST/REQ/artifact/approval or an invalid ledger hash chain is fail1; unreadable/unparseable ledger is incomplete2. These refusals apply even when the authored explicit check exits0. Preserve native characterization/weak/Refactor evidence rather than relabeling it strong Red. Later valid matching native events do not invalidate earlier still-valid selected events; unrelated ledger appends never stale a task.
Pure reads parse config as bounded fatal-UTF8 JSON and never infer disabled mode from malformed/null/array config. Enabled gate validates global structure before execution and adds, rather than substitutes for, existing native checks. Re-evaluate the selected planning closure after project checks; input/receipt/history changes cannot leave a success verdict. Native setup/exit2/output overflow is incomplete2; native conclusive rejection/ordinary nonzero check is fail1. Literal native aggregate `gate` checks cannot establish their own task completion; arbitrary trusted local check code is not inspected or sandboxed.
The literal aggregate guard conservatively recognizes argv tokens whose portable basename is `sdd`, `sdd.mjs`, `musubix6`, `musubix6.mjs` or their `.cmd` launchers, followed by a `gate` token, including project-local wrappers with those names. It refuses before execution with reason `aggregate gate cannot establish task completion`. Planning JSON exposes `errors:[{id,reason,exit}]` and task rows `{id,feature,reqs,state,fingerprint,exit,reasons}`; gate retains legacy `verdict` and adds the planning decision under `planning`, while context adds `{enabled,stage,status,exit,taskIds,reqs}` under `planning`. No logs or internal adapter objects are rendered as task rows.
Changed scope unions existing relevant REQs, native file impact, spec/artifact owners and all shared owners, then task prerequisites. Plan/config changes conservatively select the effective configured scope. Only exact ledger/approval/prepare bookkeeping paths and well-formed content-addressed receipt/attempt-log paths are exempt from unknown ownership; the ignored legacy `.sdd/plan.md` is not an enabled planning authority. Empty known-bookkeeping-only scope is permitted without certifying pending tasks; unknown paths, even outside the configured features, refuse2. All tasks still receive global structural validation.
Context uses structure, not completion, so it remains usable for replanning stale work. It closes selected full features over feature prerequisites, all their task prerequisites and shared artifact owners, adds owned task artifacts to existing declared spec artifacts, and computes a fixed point rather than rejecting cycles in an induced coarse feature graph when the validated task DAG is acyclic. Named spec/REQ selections retain existing ambiguity checks; file selections union native impact and explicit ownership. No unresolved ownership or byte overflow emits partial bodies. Existing payload fields remain and enabled output adds explicit planning stage/task/REQ metadata.
Legacy standalone copies remain supported for explicitly disabled bare `plan`, `gate` and native `tdd` commands: absence of optional sibling planning modules cannot break those command shapes. Only a proven valid explicit false planning policy permits the legacy plan/gate path. When siblings are unavailable, default/explicitly enabled planning, `plan check/verify` and `context` explicitly refuse2 without a module-loader stack; malformed config remains fail1 and unavailable/unreadable input remains incomplete2. The compatibility policy read uses the same bounded1MiB regular in-root file, fatal UTF-8/JSON and object/present-boolean-policy rules; it never guesses disabled from absent or invalid input. A lone copy is not an installed planning distribution. TEST-PLAN-CLI-005/007 pin these shapes; packaged planning still requires the complete helper bundle.

First violated condition is execution: local native stack `v027-diagnostic-workflow-validation-cnv8sm/test-logs/native-shutdown-3267530.log` shows `Environment::Exit` joining a V8 worker parked in `CollectionBarrier::AwaitCollectionBackground` after the changed gate printed PASS. Draining imports still hung; the import hypothesis is not established. This matches the primary upstream mechanism in nodejs/node#64274 and its open fix nodejs/node#66171, not proof that every earlier hosted timeout had the same native stack.
Six stages: contract preserves existing0/1/2 and disabled semantics; trusted inputs remain the same validated config/plan and declared argv; execution is the confirmed local forced-exit/GC failure; verdict requires normal OS completion and absence of forbidden exit calls, not a PASS line; evidence history retains failed diagnostics and invalidates changed-spec/task receipts; integration requires direct/wrapper/installed and original full/scoped/standalone controls. No stage is waived.
The required regression observes the actual `process.exit` and `process.reallyExit` boundaries in a preload before entry-point loading and delegates their original implementations unchanged. Synchronous, unique per-call startup/call markers live in a separate temporary directory outside the tested project. Positive controls must prove that both observers load, record the real method/arguments and preserve forced exit7. Each of the eight state/entry rows first runs an ordinary valid control, then independently checks the instrumented call's complete JSON,0/1/2 OS status and normal terminal signal. Startup markers prevent a missing observer from creating a vacuous pass. Collect forbidden-call records across all rows before the owning assertion so an isolated native reversal detects all four native states and a wrapper reversal detects all four wrapper states, not only the first success case. Restore each mutation exactly and rerun valid controls. The wrapper preload observes only its outer process; the direct leg covers the native core, without inherited `NODE_OPTIONS`.
This is an oracle replacement, not a narrower public requirement or a waiver of a runtime/state/entry/deadline. The former V8 diagnostic flag can itself stop the repaired natural path: `v027-node22-shutdown-diagnostic-IqzvhQ` captured `NodePlatform::DrainTasks` and `StressConcurrentAllocationTask`, unlike the forced-exit join above. Moving all heap/crypto work inside the forced-exit hook produced genuine native Red20398ms/Green1854ms but still failed Node22 in the unfiltered `6BZhCv` matrix, stability `UaGecM`, and mutation driver's unmodified `ApN4ef` baseline. Those failures remain retained; passing subsets are not retries-to-PASS. Remove that unsound timing oracle from required verdicts; preserve its spikes, stacks and failed samples as non-gating root-cause history. The deterministic observer proves that these real exit-property calls are avoided; it does not demonstrate elimination of every VM-GC hazard or instrument internal native exit bindings. A reference cached by entry-point JavaScript after this preload still names the observer; preexisting internal native references are outside its observation. Abort/kill signals remain rejected by the OS-completion assertions. Original full gate and same-source hosted CI must still establish integration; artificial spikes and this bounded observation are not release qualification.
Change only normal native dispatch and the wrapper's returned-child result to assign `process.exitCode`; retain early abort/conflict refusals and their exact statuses, including the wrapper's existing signal/unavailable-status mapping to1. The wrapper does not forward Node flags or preloads: the direct case observes the native process; the wrapper case independently observes the wrapper's outer process around its ordinary native child. Do not use inherited `NODE_OPTIONS` to propagate the observer. Do not mask errors, retry to PASS, pin/downgrade Node, increase required budgets, skip cases, remove input provenance or change optional-loader semantics. Reversing each of these two dispatcher changes must be detected in isolated mutations, followed by exact restoration and valid0/1/2 controls. Existing large-context transport `EAGAIN` observed in a separate spike is not caused by this change and is not included in its completion claim.
Residual risk: the shared normal dispatcher also serves gate, tdd, diagnostics, context and status. Natural shutdown can expose an unclosed handle in any of them; the planning regression alone cannot exclude that risk. Existing bounded CLI/standalone/Windows controls, actual diagnostics and the original full gate must complete normally before integration is accepted; a live-handle timeout remains blocking, not a reason for forced-exit fallback. Early unknown-flag/usage/standalone-policy refusals, spec/ledger conflicts, lock failure and the recognized REFUSED exception catch retain their existing abrupt exits, so this narrowly scoped change does not claim to remove that upstream GC risk from every abort path.
## Assumptions / risks
Exact subcommands/config key and JSON shape above are the design baseline; direct/wrapper/host fixtures must pin them. New evaluation refusals use1/2; valid disabled configurations retain legacy behavior, while malformed config explicitly refuses rather than guessing that planning is disabled.
No release authorization is added. Numeric input/output limits and cross-language impact boundaries require a pre-implementation spike; unresolved scope never succeeds. TEST-PLAN-CLI-001/003/004 retire these assumptions.
