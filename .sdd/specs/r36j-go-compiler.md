# Issue #374: truthful Go compile-checked witnesses
Goal: prevent failed Go processes from becoming successful compilation witnesses.
Non-goals: change Go command/target/inference, native probe options, legacy raw text, C/Rust behavior, existing tests/budgets, root discovery, release qualification.

| ID | EARS requirement | Test |
| --- | --- | --- |
| REQ-R36J-001 | When Go stub verification invokes its existing Go test command, the CLI shall report compile-checked only for actual status zero with no spawn error, no termination signal and no compiler diagnostic; all other outcomes, including empty/opaque/terminal-only failures and malformed outcomes, shall exit nonzero with reason priority error CODE, signal X, unavailable status, nonzero exit status, followed by supplementary compiler diagnostics, whether generation occurred or not. | TEST-R36J-EXIT-001, TEST-R36J-INVALID-001, TEST-R36J-BOUNDARY-001, TEST-R36J-MALFORMED-001, TEST-R36J-REASON-001 |

## Design
- Reuse existing shared raw `probeOutcome` unchanged: UTF-8, LC_ALL C, 120000ms, default buffer; keep legacy `probe` and approved Rust/C predicates byte-identical.
- Add Go-local outcome helper invoking the exact existing command and cwd, removing SGR once from raw text. Both existing inference passes consume its text, final verification consumes a fresh outcome.
- Decision table: error → `Go compile check failed with error CODE`; signal → `Go compile check terminated by signal X`; null/undefined status → `Go compile check failed: status unavailable`; nonzero → `Go compile check failed with exit status N`; normalized `.go:line:column` diagnostic → failed with diagnostic; only status0/no-error/no-signal/no-diagnostic → verified.
- Preserve generated deduplication and cap the complete `verifyError` at160 characters, retaining the prioritized process reason first; run final checker even when no files were generated so no-op invalid fixtures cannot silently succeed.
- Extend existing failed C/C++ stub CLI exit1 dispatch to `.go`; preserve all other language dispatch and status annotations, complete G/I EOF tails and all budgets.
- Controls use real executable native-first wrappers; malformed outcomes use Go-only preload interception, leaving git/CLI process execution intact. Colored parser wrapper delegates actual native Go and independently validates emitted diagnostics before CLI.
- Independent coordinator Sonnet review is required before spec lock or production edit. No nested agents; no root gate/full-suite claim. A later small proof runner may extract exact final EOF test/helper bytes without changing the 512KiB scanner.
